- [x] Platform agent provider assignments are validated on create/update; nested secret-like provider configuration is rejected.
- [x] Local LiveKit service/runtime acceptance covers room handoff, synthetic audio frames, authenticated lifecycle events, persisted transcript/session state, interruption, disconnect and recovery. Provider inference is deterministic/stubbed in this suite.
- [x] Alembic migrations and the cross-service session/transcript acceptance pass against an isolated PostgreSQL 16 tmpfs instance (4 acceptance tests passed); its container was stopped after verification.
- [x] Agent create/edit and conversation UI are connected to the Platform API, with explicit loading/error/empty states and unsupported Runtime providers disabled.

The inference processors are deterministic test doubles; provider quality is not verified.
- [x] Browser interruption journey streams deterministic assistant audio through Pipecat/LiveKit, confirms browser playback, then processes a follow-up transcript from browser ingress while speaking and verifies `AgentSpeechStarted` → `UserInterrupted` → `AgentSpeechCancelled` plus transcript persistence. The STT/LLM/TTS implementations are test-only substitutes; natural-speech VAD/STT behavior is not established.
- [x] Optional browser VAD journey uses a local packaged speech WAV as Chromium's fake mic source; Pipecat's configured Silero VAD emits `VADUserTurnStart` during assistant playback and the browser test observes interruption/cancellation. Nothing was copied into the repo. STT remains stubbed, so this is not provider or natural user speech acceptance.
- [x] Browser disconnect journey navigates away without calling the explicit Platform end endpoint; Runtime observes the LiveKit participant departure and Platform persists `SessionEnded` with reason `participant_disconnected`.
